# Передача сайта заказчику: свой аккаунт REG.RU и новый сервер

Схема: заказчик сам создаёт аккаунт REG.RU, домен переносится на него, сайт переезжает на новый сервер заказчика. У исполнителя не остаётся доступа к чужим данным.

Время: подготовка 1–2 часа, звонок 1 (аккаунт, сервер) 60–90 минут, перенос 1–1,5 часа без заказчика, звонок 2 (переключение и передача) 30–45 минут. От начала до конца 3–5 дней, большая часть из них ожидание передачи домена.

Команды ниже выполняются на сервере (строка начинается с `root@...`), если не сказано иначе. Не вставляйте несколько строк сразу, если они спрашивают пароль.

## 0. Подготовка (до звонка)

1. Обновить сайт на текущем сервере последней версией:
   ```
   cd /opt/site && git pull
   nohup sh -c 'docker compose up -d --build && docker compose --profile tools run --rm --build seed pnpm tsx scripts/apply-client-data.ts && docker image prune -f' > /root/deploy.log 2>&1 &
   ```
2. Проверить место и службы: `df -h /` (свободно ≥ 3 ГБ), `docker compose ps` (db, app, caddy Up).
3. Сделать бэкап и убедиться, что файлы появились:
   ```
   bash /opt/site/scripts/backup.sh
   ls -lh /opt/backups
   ```
4. Включить ночной бэкап (один раз): `(crontab -l 2>/dev/null; echo '0 3 * * * bash /opt/site/scripts/backup.sh >> /var/log/site-backup.log 2>&1') | crontab -`
5. Договориться с заказчиком о времени звонка 1. Отправить ему сообщение (шаблон ниже).

### Сообщение заказчику перед звонком 1

```
Здравствуйте! Чтобы сайт, домен и сервер были полностью вашими, мы создадим ваш личный кабинет на REG.RU и перенесём туда сайт. Это займёт около часа по видеосвязи, я всё покажу пошагово.
К звонку подготовьте:
1. Телефон, на который придёт код подтверждения (понадобится вам одному).
2. Адрес электронной почты, которой пользуетесь вы сами.
3. Банковскую карту для оплаты сервера (около 1 800 ₽ в месяц, оплата почасовая) и домена (раз в год).
4. Паспорт или данные организации на случай, если сервис запросит подтверждение.
Пароли и коды вы будете вводить сами, мне их говорить не нужно.
```

## 1. Звонок 1: кабинет заказчика, домен, сервер (60–90 минут)

Заказчик делится экраном и всё делает сам. Вы подсказываете.

1. **Регистрация в REG.RU.** reg.ru → «Регистрация». Email заказчика, телефон, пароль (длинный, записать в менеджер паролей или на бумагу). Подтвердить email и телефон кодами. Включить двухфакторную защиту в настройках профиля.
2. **Пополнить баланс.** Для сервера (почасовая оплата) нужен запас хотя бы на 2–3 месяца. Если баланс обнулится, сервер отключится, а сайт перестанет открываться.
3. **Принять домен.** Исполнитель в своём кабинете: Домены → `pcstrela.ru` → «Передать на другой аккаунт», в поле получателя логин (email или номер клиента) заказчика. Заказчик получает запрос и подтверждает в кабинете или по письму. Обычно от нескольких минут до 1–3 дней. Если пункта нет, исполнитель пишет в поддержку REG.RU: «Прошу передать домен pcstrela.ru на аккаунт <логин заказчика>».
4. **Заказать сервер.** Рег.облако → «Создать сервер»: Ubuntu 24.04, 2 vCPU, 4 ГБ RAM, диск от 40 ГБ (лучше 60 ГБ), дата-центр в РФ, **без SSH-ключа**, вход по паролю. После создания придёт письмо с IP-адресом и паролем root. Заказчик передаёт их исполнителю **одноразовой ссылкой** (Bitwarden Send или аналог, срок жизни 24 часа), не открытым текстом в мессенджере.
5. Заказчик меняет пароль root на новом сервере, когда перенос закончится (шаг 5).

Если звонок затянулся или что-то не получилось, пункты 3–4 можно разнести на два дня.

## 2. Перенос на новый сервер (исполнитель, без заказчика, 1–1,5 часа)

Новый сервер: `ssh root@НОВЫЙ_IP`.

1. Установка сайта (10–15 минут сборки):
   ```
   apt-get update && apt-get install -y git && git clone https://github.com/arturvar96355-spec/pcstrela.git /opt/site && bash /opt/site/scripts/server-setup.sh
   ```
   Скрипт спросит email и пароль админа: впишите любые, данные из бэкапа их заменят. Домен в `.env` по умолчанию `pcstrela.ru`.
2. Перенести бэкап. На **старом** сервере (замените имя файлов на свежие из `ls -t /opt/backups | head`):
   ```
   scp /opt/backups/db_ДАТА.dump /opt/backups/media_ДАТА.tar.gz root@НОВЫЙ_IP:/root/
   ```
   Введите пароль нового сервера. Если связь между серверами не проходит, скачайте файлы на свой компьютер командой `scp root@СТАРЫЙ_IP:/opt/backups/*.dump .` и загрузите на новый тем же способом.
3. Восстановить на **новом** сервере:
   ```
   bash /opt/site/scripts/restore.sh /root/db_ДАТА.dump /root/media_ДАТА.tar.gz
   ```
   Введите `yes`. В конце должно быть «Сайт работает».
4. Проверить: `curl -s http://127.0.0.1:3000/api/public/health` (ответ со `status: ok`) и `docker compose ps` (все Up).
5. Включить ночной бэкап на новом сервере (команда из шага 0.4).

## 3. Звонок 2: переключение и передача (30–45 минут)

Домен уже должен быть на аккаунте заказчика (если нет, подождите).

1. **DNS.** Кабинет заказчика → Домены → `pcstrela.ru` → «DNS-серверы и управление зоной». Должны быть DNS-серверы `ns1.reg.ru` и `ns2.reg.ru`. Записи **A** для `@` и `www`: значение НОВЫЙ_IP (старые записи с прежним адресом удалить). Записи MX и TXT от прежней почты на сервере не нужны, их можно удалить.
2. Подождать 10–30 минут. Проверка на своём компьютере в PowerShell: `nslookup pcstrela.ru` (в ответе новый IP), затем открыть `https://pcstrela.ru` в режиме инкогнито. Сертификат появится сам, обычно за 1–5 минут после обновления DNS.
3. **Админ сайта.** На новом сервере создать админа заказчика и удалить своего:
   ```
   cd /opt/site
   read -p "Email админа: " NEW_ADMIN_EMAIL; read -s -p "Пароль (12+ символов): " NEW_ADMIN_PASSWORD; echo
   export NEW_ADMIN_EMAIL NEW_ADMIN_PASSWORD
   export REMOVE_ADMIN_EMAIL=ВАШ_АДРЕС_АДМИНА
   docker compose --profile tools run --rm -e NEW_ADMIN_EMAIL -e NEW_ADMIN_PASSWORD -e REMOVE_ADMIN_EMAIL seed pnpm tsx scripts/set-admin.ts
   ```
   Пароль вводит сам заказчик, вы не должны его видеть.
4. Заказчик входит в `https://pcstrela.ru/admin` и проходит по инструкции из `CLIENT_GUIDE.md` (фото, текст, объект).
5. **Пароль root.** Заказчик на новом сервере (или вы вместе с ним, он вводит): `passwd`. После этого у исполнителя нет доступа к серверу.
6. **Открыть сайт для поисковиков** (по желанию заказчика): `bash /opt/site/scripts/open-site.sh`.
7. Показать, где платить и когда продлевать (см. ниже).

## 4. После звонка

- Старый сервер (ваш аккаунт): подождать 1–2 дня, убедиться, что на новом всё работает, скачать последний бэкап себе (хранить месяц), затем удалить сервер.
- Удалить у себя все пароли заказчика и привязку своей карты к чужим услугам.
- Репозиторий кода на GitHub: сейчас он открыт, в нём данные компании. Закрыть его (Settings → Danger Zone → Change visibility → Private) можно, когда обновления будет делать только исполнитель с токеном. Решить с заказчиком, кто ведёт обновления сайта дальше.
- Продление почты на вашем аккаунте больше не нужно, если почту на домене заказчик не использует. Если нужна почта на домене, заказчик подключает её сам в своём кабинете.

## 5. Что и когда платит заказчик

| Что | Как часто | Что будет, если не платить |
|---|---|---|
| Сервер (Рег.облако) | почасовая оплата с баланса | при нулевом балансе сервер отключается, сайт не открывается |
| Домен pcstrela.ru | раз в год (автопродление включить) | сайт перестанет открываться, домен можно потерять |
| Бэкапы | бесплатно, на самом сервере | раз в месяц скачивать копию на свой компьютер |

## 6. Проверка перед закрытием (чек-лист)

- [ ] `https://pcstrela.ru` открывается с замком, `www` ведёт на основной адрес.
- [ ] Заказчик вошёл в админку своим паролем и изменил фото и текст.
- [ ] Тестовая заявка с сайта появилась в разделе «Заявки».
- [ ] Бэкап создаётся ночью, одна копия скачана.
- [ ] Заказчик сменил пароль root, пароль REG.RU и включил двухфакторную защиту.
- [ ] У исполнителя нет действующих паролей заказчика.
- [ ] Заказчик ответил сообщением «принял».
