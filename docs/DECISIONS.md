# Решения по проекту

Дополняет `SPEC.md`. При расхождении побеждает этот файл.

## 1. Исходные данные о компании (из презентации заказчика)

- Юрлицо: ООО «ПК Стрела», входит в группу компаний «МНК ГРУПП».
- Специализация: вентилируемые навесные фасады, противопожарные двери, декоративные решётки и ограждения, МАФ, уличная и складская металлическая мебель, металлические системы хранения, уличные спортивные тренажёры, элементы фасадов (металлокассеты, корзины для кондиционеров, козырьки, навесы), модульные тепловые узлы, шумозащитные кожухи. С 2026 года — проектирование котельных узлов и производство теплового оборудования.
- Производство: лазерная резка листового металла, гидравлические листогибочные прессы, сварочные установки, камеры порошковой полимерной окраски, упаковочные и такелажные средства.
- В презентации есть реальные объекты (стройка школы, капремонт поликлиник и больниц, спортивные комплексы и др.). Они станут стартовыми объектами портфолио. Заказчик объекта по умолчанию скрыт (`showCustomer = false`).
- Название, фото производства и объекты берутся из презентации. Заказчика по ним не опрашиваем.

## 2. Принцип «минимум контакта с заказчиком»

- Сайт запускается на контенте из презентации. Всё, чего нет (реквизиты, документы, сертификаты, цифры), подставляется позже через админку и не блокирует запуск.
- Любое пустое поле скрывает свой блок (это уже есть в SPEC). Выдуманных цифр, документов и отзывов на сайте нет.
- Домен, хостинг, почта, боты и Яндекс-сервисы настраивает исполнитель. Заказчику передаётся только логин от админки и короткая инструкция.

## 3. Сокращение объёма (относительно SPEC)

Оставляем: публичные страницы из 0.4, каталог, объекты, документы, заявки, админку, поиск, SEO, cookie-баннер.

Убираем или упрощаем:

| Было в SPEC | Стало |
|---|---|
| MAX как канал уведомлений | Не делаем. Email и Telegram |
| Яндекс SmartCaptcha | Не делаем. Honeypot, rate limit, проверка Origin |
| Повтор уведомлений по cron, удаление старых заявок, письмо об истекающих документах | Не делаем. Уведомления отправляются с 3 попытками, статус канала пишется в заявку |
| Скрипты бэкапа в S3, fail2ban, мониторинг диска | Простой `scripts/backup.sh` (pg_dump + архив media, хранение на сервере) |
| Счётчики на дашборде админки | Не делаем |
| Правило R-14 про нерабочее время и `holidays.ts` | Не делаем |
| Отдельный поддомен dev с basicauth | Не делаем |
| Коллекция `partners` и блок «Партнёры» | Не делаем (блок и так выключен по умолчанию) |
| Подробный `docs/QA.md` | Короткий чек-лист |

Остаётся по SPEC: хуки каталога (slug, атрибуты, водяной знак), правила доступа, валидаторы, ISR с revalidate, JSON-LD, sitemap, robots, заголовки безопасности, Docker Compose + Caddy.

## 4. Стек

Без изменений: Next.js, Payload CMS, PostgreSQL, Tailwind v4, Docker Compose + Caddy, хостинг в РФ (152-ФЗ). Версии выбираются по совместимости Payload 3.x с Next.js.

## 5. Отклонения от SPEC, принятые при реализации

| Что | Как сделано | Почему |
|---|---|---|
| ISR | Страницы рендерятся на каждый запрос (`dynamic = 'force-dynamic'`), данные читаются из БД | Сборка в Docker не имеет доступа к БД; нагрузка сайта небольшая |
| Скелетоны `loading.tsx` | Не используются | Они отдают статус 200 вместо 404 для несуществующих страниц |
| shadcn/ui | Собственные небольшие компоненты (`Button`, `Modal` на `<dialog>`, `Badge` и др.) | Меньше зависимостей, нет обращения к внешнему реестру |
| Шрифты | `@font-face` с файлами в `public/fonts` (Inter, Manrope) | Тот же результат, что и `next/font/local`: шрифты со своего сервера |
| Миграции | `prodMigrations` в адаптере БД: применяются при старте приложения | В образе нет CLI Payload |
| Год объекта | Необязательное поле | В презентации заказчика годов нет, выдумывать их нельзя |
| Обложка направления, текст страниц, фото главной | Необязательные | Заполняются после запуска, пустые блоки скрываются |
| Версии | TypeScript 5.9, ESLint 9 | Новые мажорные версии несовместимы с плагинами |
