# Инструкция по запуску и передаче сайта

Пошаговые действия для исполнителя. Выполнять по порядку. Значения в `<угловых скобках>` подставить свои.

Имена кнопок в интерфейсах сервисов меняются. Если кнопки нет на месте, ищите по названию раздела.

---

## 0. Что понадобится заранее

- Домен (шаг 1) и VPS (шаг 2).
- Почта на домене (шаг 3), Telegram (шаг 4).
- Менеджер паролей. Все пароли и токены складывать туда, не в мессенджеры.

---

## 1. Домен

Рекомендуемый вариант: домен в зоне .ru сразу на юрлицо заказчика. Так не будет переоформления и привязки к вашим личным данным.

1. Возьмите у заказчика (одним сообщением): полное наименование, ИНН, ОГРН, email компании.
2. Выберите регистратора в зоне .ru (например Reg.ru, Timeweb, Beget). Зарегистрируйте домен на организацию: в анкете выберите «Юридическое лицо» и внесите данные из пункта 1.
3. Пройдите подтверждение данных, которое потребует регистратор. Для организации оно делается по данным ЕГРЮЛ. Если сервис потребует вход от имени руководителя через Госуслуги или документы, попросите заказчика один раз подтвердить. Точный порядок уточните у регистратора, правила меняются.
4. Включите в панели регистратора автопродление и двухфакторную защиту входа.
5. Домен пока не привязывайте, сначала получите IP сервера (шаг 2).

Запасной вариант: регистрация на вас как на физлицо. Тогда домен привязан к вашему подтверждению личности, и при передаче потребуется смена владельца (шаг 10, пункт 1).

## 2. Сервер (VPS в России)

1. Закажите VPS: Ubuntu 24.04, минимум 2 vCPU, 4 ГБ RAM, 40 ГБ диска. Дата-центр в РФ.
2. Получите от хостинга IP-адрес и пароль root.
3. Подключитесь: `ssh root@<IP>`.
4. Обновите систему: `apt update && apt upgrade -y`.
5. Создайте ключ на своём компьютере, если его нет: `ssh-keygen -t ed25519`.
6. Скопируйте ключ: `ssh-copy-id root@<IP>`.
7. Проверьте вход по ключу из второго окна терминала. Только после этого отключите пароль:
   - откройте `/etc/ssh/sshd_config`;
   - поставьте `PasswordAuthentication no`;
   - выполните `systemctl restart ssh`.
8. Включите файрвол:
   ```
   ufw allow 22
   ufw allow 80
   ufw allow 443
   ufw enable
   ```
9. Установите Docker: `curl -fsSL https://get.docker.com | sh`. Проверка: `docker compose version`.

## 3. DNS и почта

1. В панели регистратора откройте DNS-записи домена.
2. Создайте запись **A**: имя `@`, значение `<IP сервера>`.
3. Создайте запись **A**: имя `www`, значение `<IP сервера>`.
4. Подождите до часа, проверьте: `ping <домен>` должен показать ваш IP.
5. Почту на домене заведите в Яндекс 360 для бизнеса (360.yandex.ru): подключите домен, добавьте MX, SPF и DKIM записи, которые покажет сервис.
6. Создайте ящик для сайта, например `noreply@<домен>`, и ящик менеджера для заявок.
7. Для ящика `noreply` создайте пароль приложения: Яндекс ID → Безопасность → Пароли приложений → Почта. Этот пароль пойдёт в `SMTP_PASS`.

## 4. Telegram-бот для заявок

1. В Telegram найдите `@BotFather`, отправьте `/newbot`.
2. Введите название и имя бота (оканчивается на `bot`).
3. Скопируйте токен. Он пойдёт в `TELEGRAM_BOT_TOKEN`. Никому не показывайте.
4. Создайте группу для менеджеров и добавьте туда бота и менеджеров.
5. Отправьте в группе любое сообщение.
6. Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates`.
7. Найдите в ответе `"chat":{"id":-100...}`. Число вместе с минусом и есть chat_id. Его внесёте в админке (шаг 7).
8. Если ответ пустой, напишите в группу ещё сообщение и обновите страницу.

## 5. Яндекс Метрика и Вебмастер

1. На metrika.yandex.ru создайте счётчик для домена. Скопируйте номер счётчика (цифры).
2. На webmaster.yandex.ru добавьте сайт, выберите подтверждение через мета-тег. Скопируйте значение `content` тега.
3. Оба значения внесёте в админке (шаг 7).
4. После запуска в Вебмастере отправьте `https://<домен>/sitemap.xml`.

## 6. Установка сайта на сервер

1. На сервере: `mkdir -p /opt/site && cd /opt/site`.
2. Клонируйте репозиторий: `git clone <адрес репозитория> .`.
3. Создайте файл настроек: `cp .env.example .env`, затем `nano .env`.
4. Заполните:
   - `NEXT_PUBLIC_SITE_URL` — `https://<домен>`;
   - `PAYLOAD_SECRET`, `POSTGRES_PASSWORD` — выполните `openssl rand -hex 32` для каждого;
   - `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` — из шага 3;
   - `TELEGRAM_BOT_TOKEN` — из шага 4;
   - `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD` — ваш вход в админку, пароль от 16 символов.
5. Ограничьте права: `chmod 600 .env`.
6. В `Caddyfile` замените `example-zavod.ru` на ваш домен.
7. Запустите: `docker compose up -d --build`.
8. Проверьте: `docker compose ps` (все сервисы Up) и откройте `https://<домен>/api/public/health`. Должен вернуться `status: ok`.
9. Если сайт не открылся, смотрите логи: `docker compose logs app --tail 100`.

## 7. Первая настройка в админке

1. Откройте `https://<домен>/admin`, войдите данными из `.env`.
2. Смените пароль в профиле.
3. «Настройки сайта» → вкладка «Уведомления»: внесите email менеджера и Telegram chat_id из шага 4.
4. Вкладка «Аналитика»: номер Метрики и код Вебмастера из шага 5.
5. Вкладка «Контакты»: телефон, email, адрес производства.
6. Отправьте с сайта тестовую заявку и убедитесь, что письмо и сообщение в Telegram пришли.

## 8. Резервные копии

1. Проверьте скрипт: `bash /opt/site/scripts/backup.sh`. В `/opt/backups` появятся два файла.
2. Добавьте в cron: `crontab -e`, строка `0 3 * * * bash /opt/site/scripts/backup.sh`.
3. Один раз проверьте восстановление дампа в отдельную базу (команды в `scripts/backup.sh`, раздел в конце).
4. Раз в месяц скачивайте свежий архив на свой компьютер.

## 9. Обновление сайта

1. `cd /opt/site && git pull`.
2. `docker compose build app && docker compose up -d app`.
3. Миграции базы применяются при старте контейнера.

## 10. Передача заказчику

1. **Домен.**
   - Если домен сразу оформлен на организацию заказчика: заведите заказчику аккаунт у регистратора или передайте ему вход, включите двухфакторную защиту, смените пароль.
   - Если домен на вас как на физлице: в панели регистратора найдите «Смена администратора домена» (или «Передача прав»). Новым владельцем укажите организацию заказчика. Она должна пройти подтверждение, а вы подтвердить передачу. Срок и документы уточните у регистратора.
   - Другой путь: перенос к другому регистратору по коду передачи (auth-code) с сохранением владельца.
   - Пока идёт переоформление, сайт работает, DNS не трогайте.
2. **Сервер.** Перенесите VPS на аккаунт заказчика у хостинга (вариант «передать услугу») или оставьте на себе с договорённостью об оплате. Решите это до запуска.
3. **Почта Яндекс 360.** Назначьте заказчика администратором организации.
4. **Метрика и Вебмастер.** Откройте заказчику доступ: «Настройки → Доступ».
5. **Админка сайта.** Создайте заказчику пользователя с ролью «Редактор»: «Пользователи → Создать». Временный пароль передайте лично, не в мессенджере. Попросите сменить при первом входе.
6. **Что передать одним сообщением:** адрес сайта и админки, логин, короткая инструкция «как добавить товар, объект, документ», ваш контакт на случай проблем.
7. Доступы с правами admin оставьте у себя.

## 11. Чек-лист перед запуском

- [ ] `https://<домен>` открывается с замком, `www` ведёт на основной домен.
- [ ] Главная, каталог, карточка товара, объекты, контакты открываются с телефона.
- [ ] Тестовая заявка пришла на почту и в Telegram.
- [ ] В админке заполнены телефон, email, адрес.
- [ ] Бэкап создан.
- [ ] Метрика видит визит, Вебмастер принял sitemap.
- [ ] Заказчик может войти в админку и добавить товар.
